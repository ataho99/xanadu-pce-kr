# 01. 디스크 구조

모든 일은 디스크에 무엇이 어디에 있는지 아는 데서 시작했습니다. 『바람의 전설 제나두』는 PC엔진 슈퍼 CD-ROM² 디스크 한 장에 음악 트랙과 데이터 트랙이 섞여 들어 있습니다. 아래 내용은 정적 분석과 에뮬레이터 관측으로 확인한 것이며, 실기 확인은 아직 하지 못했습니다.

## 데이터 트랙은 두 벌

데이터 트랙은 2번과 17번, 두 곳에 같은 구조로 한 벌씩 들어 있습니다. 게임이 상황에 따라 어느 쪽을 읽을지 알 수 없으므로, 한글 데이터를 넣을 때는 두 트랙을 언제나 똑같이 고칩니다. 나머지 트랙은 음악이라 손대지 않습니다.

## 디렉터리와 블록

데이터 트랙 시작에서 0x4000바이트 떨어진 곳에 디렉터리가 있습니다. 항목 하나는 「종류 · 번호 · 시작 섹터(3바이트) · 섹터 수(2바이트)」로 되어 있고, 각 항목이 데이터 덩어리 하나를 가리킵니다. 이 덩어리를 이 문서에서는 **블록**이라고 부릅니다.

블록은 대부분 챕터 하나 분량입니다. 디렉터리 번호에서 0x10을 빼면 챕터 번호가 됩니다. 예를 들어 번호 0x10은 챕터 0이고, 섹터 435부터 80섹터(163,840바이트)를 차지합니다.

블록들은 디스크 위에 빈틈 없이 이어 붙어 있는 경우가 대부분입니다. 그래서 블록 하나를 키우려면, 섹터 끝까지 남은 몇백 바이트를 쓰거나 디스크 끝의 빈 공간으로 블록을 옮기고 디렉터리를 고쳐야 합니다. 챕터 0 블록 바로 뒤 8섹터에는 아직 정체를 확인하지 못한 데이터가 있어서, 이 블록은 80섹터를 넘기지 않습니다.

## 섹터와 오류 검사

데이터 섹터는 Mode 1 형식입니다. 2,048바이트의 데이터 뒤에 오류 검출 코드(EDC)와 오류 정정 코드(ECC)가 붙습니다. 데이터를 한 바이트라도 바꾸면 이 두 코드를 다시 계산해야 하고, 빌더는 빌드가 끝날 때마다 디스크 전체 섹터를 다시 검사합니다.
